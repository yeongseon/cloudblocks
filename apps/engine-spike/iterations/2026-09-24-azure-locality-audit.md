# Experiment correction: Azure resource locality

- Date / issue: 2026-09-24 / #1927
- Question: Does the study distinguish hosted Azure PaaS resources from subnet-resident resources and model only relationships the current schema can actually express?
- Stop condition: fail if a PaaS service block appears on a subnet, an unsupported VNet Integration or private endpoint target link is invented, or the production fixture validation rejects the corrected study.

## Verification and decision

- Corrected baseline and dense fixtures pass placement, import shape and connection tests; new assertions keep the hosted PaaS types at root. Actual SVG editor baseline is rebuilt and recaptured.
- Cross-subnet movement checks use Application Gateway rather than App Service. Accepted transfer remains an **interaction test**; not a claim that moving a gateway into a shared data subnet is a valid Azure deployment.
- Keep this corrected rendering study but **do not claim provider deployability**. A future product-model decision must separate managed service, subnet NIC/private endpoint, outbound integration and gateway-dedicated-subnet constraints before offering Azure-specific validation or IaC export guarantees. See `REVIEW.md` for the remaining gate.
